# Architecture and implementation boundaries

React 19 + TypeScript + Vite builds a static, local user interface. FastAPI on loopback port 8765 processes files, renders labels with Pillow/python-barcode, reads Odoo JSON-2, stores the queue and job history in SQLite, and submits to Windows via pywin32. No cloud hosting, CDN, remote fonts or product-data service is required for offline work. Python 3.12 and Node 22+ are development prerequisites.

`backend/models.py` is the trusted boundary. Prices are Decimal and serialize as strings; barcode fields cannot be numbers. `layout.rows` expands the common queue deterministically with no filler products, preserving exact quantities and order. Every invocation begins at LEFT. `render.label` checks glyph coverage, shaping availability, complete text fitting, barcode encoded width, two-dot minimum modules and ten-module quiet zones. Font sizes never shrink below twelve dots. Unfittable strings produce errors instead of truncation. Text and price use a bold font when the font family has one. `raster_row` combines labels. That same bitmap is used for PNG preview, GDI driver output and raw TSPL BITMAP output. There are no browser print headers, CSS margins or fit-to-page scaling.

Millimeters convert using Decimal half-up rounding of absolute positions at 203 DPI; columns do not accumulate rounded pitches. TSPL emits one CLS/BITMAP/PRINT 1,1 per physical row, including a partly used final row. It never emits barcodes or outlines in unused positions. Native feeding and row origins still require verification on the device. GDI refuses incompatible DPI, hardware margins and insufficient paper size rather than resizing the job.

Security: loopback-only server, exact Host allowlist, Origin and fetch-site checks, no CORS, random per-process session capability required for API operations. Same-origin code obtains it through a session endpoint that other origins cannot read. Print requests are schema validated and require a calibration fingerprint tied to all settings, printer and method. Persistent unique job IDs reserve a submission before touching the spooler. Failed or uncertain submissions are never automatically retried. A service restart preserves IDs. The local OS user remains the trust boundary; this is not a multi-user network service. Do not run multiple backend workers.

Odoo requests allowlisted read-only methods, validate *.odoo.com HTTPS, verify TLS, refuse redirects, redact transport failures, and keep credentials in the backend. Windows writes directly to WinVaultKeyring (no plaintext fallback). Linux development supports explicitly injected environment variables. No key enters queue persistence or exports. Configuration deliberately supports Odoo SaaS rather than arbitrary network URLs. Pricelist price calculation remains blocked until a public operation and its inputs can be verified for the actual database. Never substitute Sales Price for a pricelist result.

SQLite retains a single local workspace in `.local` by default. Exported queue JSON passes the same backend schema before replacement. Identical products remain independent. Import sources are never merged automatically. Imported spreadsheet files stay local; macros and formulas are not executed. XLSX formulas are rejected rather than trusting missing caches. Legacy XLS library exposes cached values, so the importer warns about formula/numeric review. CSV uses UTF-8 and deterministic supported heading aliases. A sample template makes decimal and quantity conventions explicit.

Tests exercise pure layout, actual supplied workbook, rendering, geometry, imports, API authorization, duplicate submissions and mocked Odoo wiring. Mock tests do not establish live Odoo availability. Hardware, Windows native execution and packaged release verification remain separate.
